Rasgo Synth -- architecture flowchart (phase84 baseline, operational update 2026-08-22)

Replaces the Mermaid flowchart published as an artifact in phase 38 (and the illustrated/blueprint version redesigned afterward, both outside the repository -- this session has no access to an artifact-publishing tool, so this version lives as a versioned file, which has the advantage of never silently going stale again). Five parts: seed-time choices, per-sample signal flow, the mastering chain, mechanism classification, and a map of cross-coupling/symbiosis between them. Updated from phase76 to phase84 -- Harmonàig/sieve polyphony/Bloom (77-79), Caillois game weights (80, now its own cross-bias hub, see Part 5), aksak/rhythmic sieve (82), and Curto-Circuito ("Short-Circuit", 84).

Every mechanism cited carries its origin phase in parentheses -- see Plano_de_Upgrade_Instrumento_Generativo.md (Portuguese only) for the full history of any of them.

The phase84 diagram remains the structural baseline. Phases 118-123 added material agency, post-space audibility ecology, relational orchestration and memory; the current reference and continuity documents describe those additions without duplicating every edge in this flowchart.

Part 4 -- mechanism classification

Not an exhaustive list of every mechanism in the engine (that would duplicate the entire Plano_de_Upgrade_Instrumento_Generativo.md) -- it's a classification by structural type, the question "what kind of decision is this, and what does it compete or not compete with." Every engine mechanism falls into one (or more) of these five categories:

A. Single structural choice (runs once, decides between mutually exclusive alternatives)

The seed decides a fork and only one side exists for the whole piece -- never both at once, this project's own "one clean mode, not layers" discipline.

Mechanism (phase) Mutually exclusive alternative
Polivoks filter (75) SallenKeyFilter -- same crossfade slot with MoogFilter
Neo-Riemannian P/L/R (65) Fixed chord progression I-IV-V...
Semitone-distance voice leading (62) Scale-degree index voice leading (default)
Xenakis sieve scale (61) 39-scale catalog (default)
16-step rhythmic archetype (67/82) Default XOR divider for kick/snare/hihat
Euclidean cowbell (57) Cowbell via the default XOR divider
Modal modulation (33) Tonal modulation (32/48)
Polyphonic cascade/Shifty (63) Simple additive hocketing (37)
Coda ritardando (48) Accelerando/stringendo (68) -- ritardando wins if the coda genuinely arrives
Per-piece scale (48) No longer forced by an album theme (phase 83) -- every piece, album or not, rolls its own

B. Independent additive layer (on/off, doesn't compete for a "slot")

Mixes in continuously when enabled, alongside whatever else is happening -- no conflict, just presence or absence.

Examples: Walsh oscillator (59), VOSIM (72), Vector Synthesis (76), chaotic binaural beat (73), tuba/breath voice (43), granular cloud, ring modulator, multiband bloom, tom ratchet/cymbal sustain (56), Harmonàig (77, conditioned on an active chord progression), Xenakis sieve polyphony (78), Bloom (79).

C. Direct cross-coupling (one mechanism's output modulates another's parameter/state)

The most "alive" point of the architecture -- where a mechanism isn't just an isolated effect, but genuinely feeds another. See the full map in Part 5.

Examples: cross-domain contagion (60, audio peak -> extra pulse into the clock divider), sidechain asphyxia (74, kick -> filter cutoff), Heisenberg (71, one balance -> rhythm AND pitch in opposite directions), Vector Synthesis (76, two chaos maps -> crossfade X/Y position), Agon (49, melodic staleness -> power redistribution across 4 voices), Caillois game weights (80, four weights -> probability bias for eleven mechanisms), album trajectory (83, two simplex points -> an interpolated point per track).

D. State persisted between renders (survives the end of the piece)

A rare category -- the overwhelming majority of the engine is 100% deterministic from the seed, with no memory between runs. Only two exceptions, both honestly documented in the JSON:

  • Strange element, literal version (50-51): reads the real CPU temperature/load at render time -- the same seed can produce slightly different pieces.
  • Probability market (69): eight recent mechanisms (see the table in Part 5) trade a fixed probability for a "price" with a mean-reverting random walk, persisted in .rasgo_market.txt, bounded 0.03-0.97.

E. Safety net / forced activation (fires in reaction to other mechanisms)

Two mechanisms use the same idiom -- flip a flag and configure the object right there -- but from opposite triggers:

  • Intensity guarantee (phase 40): checks whether apocryphal + free intonation + tonal modulation + self-feedback all came up "no" by chance, and forces one of them BEFORE the main loop even starts -- every piece genuinely tests at least one risk mechanism.
  • Curto-Circuito (phase 84): in the MIDDLE of the piece, a real hard cut fires and, at the same instant, gives an elevated second chance (40% each) to six mechanisms that had already rolled "no" at the start (apocryphal, free intonation, tonal modulation, self-feedback, rungler, strange element) -- the same forced-activation idiom, but reacting to a rupture, not to a total absence of risk.

A note on honesty

Every seed-gated mechanism above appears in the metadata JSON and in the .txt score as a real true/false -- never "present but never tested." This project's discipline (see the history of bugs caught by empirical verification, not just a clean compile) is: every new mechanism is audited across a batch of rendered pieces before being considered done, counting how often the field shows up as true and comparing it with the expected probability -- including, at phase 76, a process bug caught this way (a stale binary without the new phase's code, exposed by a statistically impossible firing rate before any human ear needed to notice), and at phase 84, a real audit across 22 pieces confirming Curto-Circuito firing and listing by name which mechanisms gatecrashed.

The probability market (phase 69, Part 5 above) is the only category where the probability itself isn't fixed -- but the value actually used in each piece stays exposed in the JSON (marketPrices), so the audit's honesty isn't compromised by that.
